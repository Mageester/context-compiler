Architecture

How it builds context

Four layers transform your natural language description into a perfect, token-budgeted context window.

🫀 Layer 1: Intent Parser

Tokenizes your natural language task and identifies which code domains it touches — auth, database, UI, API, etc.

🔗 Layer 2: Semantic Index

A pre-built embedding index of every file in your codebase. Built once, queried instantly. Includes the full dependency graph.

⚡ Layer 3: Relevance Engine

The brain. Scores every file using a composite of semantic similarity, dependency graph proximity, and past usage history.

✂️ Layer 4: Context Compiler

Trims each file to keep only what matters — function signatures, types, core logic. Strips boilerplate, comments, dead code.

The Brain

Three signals that decide what matters

Given a natural language task + a codebase, the engine ranks every file by relevance using a composite score.

50% weight

🫀 Semantic Signal

The compiler pre-builds an embedding vector for every file — a summary of what each file does. When you describe your task, it finds the closest files by cosine similarity.

"Fix auth race condition" is semantically closest to auth-middleware.ts because the embedding model knows "auth" + "race condition" = concurrency bug in auth code.

30% weight

🔗 Dependency Signal

The compiler builds a full dependency graph from your imports. When a file is relevant, its dependencies get bonus weight — ensuring the coding agent sees why the code works.

auth-middleware.ts imports session-store.ts → gets included automatically.

20% weight

📊 History Signal

Learns from your past sessions. Files included in successful compilations for similar tasks get a bonus. Over time it gets more accurate at predicting what works for your codebase.

session-store.ts was used 8x in past "auth" tasks → automatically boosted.

✂️ After scoring

Trimmer — keep only what matters

After ranking, each file is trimmed to remove boilerplate — keeping function signatures, type definitions, core logic. Strips comments, console.logs, and dead code.

500-line file → 120-line context, preserving all the LLM needs.

Tech Stack

What powers it

🦀 Rust

Single binary, native performance, no runtime. Needs to parse large codebases fast and run embeddings in-process. A single curl | sh install.

🗃️ SQLite + FTS5

Full-text search for file discovery. Embedded, zero-server, ACID. The index lives in a .ctx/ folder inside your project — no daemons, no databases to manage.

🧠 ONNX Runtime

Local, offline embedding. No API calls. Runs a mini model (all-MiniLM-L6-v2, 22MB) in-process. Works on a plane. Privacy by default — your code never leaves your machine.
